# PRD — Community Water Quality Reporting (v2: no evidence, no pre-moderation)

## Policy
| Item | Decision |
|---|---|
| Account | None |
| Photo | Not collected at all |
| Required fields | Event type, GPS location, time (default now) |
| Description | Optional, ≤300 chars |
| Publish | Immediately, status **Unverified** |
| Pre-moderation | None; review only flagged / high-risk reports afterwards |
| IP | Stored backend-only; never in public data |

## Abuse prevention
Turnstile → blocklist check → 10-minute rate bucket per HMAC(IP) → risk score → publish.
Thresholds: 1–3 ok, 4–5 +risk, >5 throttle, ≥15 auto-block 24 h (admin can unblock). Never permanent from IP alone.
Admin: reports per IP (1h/24h/7d), risk reasons, block/unblock, bulk hide.

## Data (Firestore)
`reports` (public fields) · `ip_raw` (30 d TTL) · `submission_meta` (ip_hash, UA, risk, flags; 180 d TTL) ·
`ip_restrictions` (doc id = ip_hash, expiresAt) · `block_audit` (180 d) · `rate_buckets`, `dup_keys` (short TTL).

## Architecture & cost
GitHub Pages (static, hourly rebuild) + Firebase Functions + Firestore. Reads are free-tier (data baked at build time).
Projected: ~$0/mo up to ~100k visits and ~30k reports/mo; cost then scales with function/Firestore writes only.
GitHub Pages soft bandwidth limit ≈100 GB/mo — put Cloudflare's free proxy in front or move tiles off-site beyond that.

## SEO
Static HTML, Thai metadata, canonical, OG, JSON-LD (WebSite, FAQPage, BreadcrumbList, Article), sitemap (zero-report provinces excluded and noindex), robots.txt, per-province landing pages, lazy-loaded map.

## Privacy / PDPA
Notice states purpose (spam/security), retention (30/180/180 d), access (admins only), contact. Needs legal review.

## Front end v3 (Clearwater Watch)
- Product name: **Clearwater Watch** (Thai tagline "แผนที่เฝ้าระวังคุณภาพน้ำของประเทศไทย"). Single source: `SITE_NAME` / `SITE_TAGLINE` in `src/lib/types.ts`.
- Languages: Thai (default, existing URLs) and English under `/en/` (home, report, provinces, guide, about, privacy). Dictionary: `src/lib/i18n.ts`; pages are shared components in `src/components/pages/` with a `lang` prop. `hreflang` th/en/x-default (= Thai), per-language canonical, sitemap with i18n alternates. `/admin/` is English-only and noindex.
- Three sources with distinct marker shape + colour: Official (square, PCD WQI via data.go.th, Open Data Common), News (diamond, with article links), Community (circle, "Unverified"). Filter chips filter map and list client-side (data is embedded in the page; no extra requests).
- Stats are source-aware: time windows apply to community reports only; news and official items show totals with their latest date/year.
- Report flow: type → location (GPS or map pick, province suggested) → send; time defaults to now and details are optional (collapsed). API contract unchanged.

## v4 — Toxic-substance river alerts
- Pages: `/toxic/` (Thai) and `/en/toxic/` (English); header nav entry "แจ้งเตือนสารพิษ / Toxic alerts", home strip card, and a results section on province pages that have measurements.
- Data: `src/data/measurements.json` (regenerated by `npm run fetch-data`). These are official PCD lab results **as reported by news**; every row links its article. Helpers in `src/lib/toxic.ts` (latest per station+substance+matrix, ratio = value/standard, per-river summaries, arsenic history across rounds).
- Levels (styled by icon + border style, not colour alone):
  - **Confirmed exceedance**: `exceedsStandard === true` as stated by the article/agency. We never compute our own exceedance flags.
  - **Watch**: no Thai standard (e.g. aluminium) and the agency says to keep monitoring. Never called "exceeds".
  - **Not detected / within standard**: below the detection limit or within the standard.
  - News-only suspicions (no lab result) stay on the main map as "Unverified" and are never alerts.
- Data rules: water (mg/L) and sediment (mg/kg, not drinking-water values) are always shown separately; the value-vs-standard bar and "N× the standard" only appear when the article gave a standard; every reading shows its sampling dates and round; locations are approximate reference points; no health advice of our own (we point to PCD and the Department of Health).
- Channels (no push messaging): the on-site page and its status strip; Atom feeds `/toxic.xml` and `/en/toxic.xml` (one entry per river + round + sample type with confirmed exceedances, linking the source article) with a "Follow via RSS" block and copy-link button; a "Share this alert" button (`navigator.share`, copy-link fallback for LINE/Facebook).
